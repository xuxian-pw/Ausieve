# 测试

用法和参数见 [README](../README.md)。

```powershell
cargo test -- --nocapture
```

测试在单机上用真实音频设备运行（不 mock），全部跑完约 30 秒，期间会从默认播放设备放出 -20dBFS 的测试音。
每个进程用不同频率的正弦波标记（被排除的 A 是 1000Hz，保留的 B 是 440Hz），用 Goertzel 算法测频点电平，
用 FFT 互相关测延迟。每次都同时录两路：虚拟声卡的录音端，以及测试音所在播放设备的 loopback（即本地实际听到的声音），后者作为参照。

| 用例 | 断言 |
|---|---|
| t1 按 PID 排除 | 440Hz 存在，1000Hz 比 440Hz 低 ≥40dB |
| t2 对照组 | 排除一个无关进程时，两个频率都到达虚拟声卡，电平与本地输出相差 <3dB |
| t3 无回环 | B 只播放 200ms；虚拟声卡里的声音不能比本地更响、更长，本地静音 80ms 后虚拟声卡也必须静音 |
| t4 进程重启 | 按名字排除，A 被杀掉后重新启动（PID 变化），仍然被排除 |
| t5 子进程出声 | A 本身不出声，由它启动的子进程出声；按名字排除根进程仍然有效 |
| t6 延迟 | 30ms 脉冲在本地输出与虚拟声卡之间做互相关（两路都按 QPC 时间戳对齐），断言 < 50ms |
| t7 按路径排除 | 两个**同名**程序放在不同文件夹，只排除指定路径的那个；它重启后仍然被排除 |
| t8 托盘程序 | 启动时恢复已保存的配置并排除；切换到“不排除”后再切回来，立即生效，并且配置文件已写回磁盘；构建并弹出右键菜单后程序不崩溃 |
| t9 输出出错重试 | 输出设备不存在、或被其他程序独占时报告错误，设备空出来后约 2 秒内自动恢复，声音照常 |
| t11 静音后出声 | capture 已经运行、5 秒什么都不播放之后，再开始播放正弦，从第一个采样起检查虚拟声卡里的波形有没有断点（模拟音量提示音） |
| t12 静音底噪开关 | 关：静音期间虚拟声卡里全是精确的零（行为不变）。开：没有一个采样是精确的零，电平 < -80dBFS；正弦照样无断点地通过 |
| t10 启动无杂音 | 一个连续的 1000Hz 正弦在播放时启动 capture，逐个采样检查虚拟声卡里的波形（纯正弦的二阶预测残差），启动后不允许出现断点、丢样或重复 |
| t13 快速连续点音量 | 连续的 1000Hz 正弦播放时，另一个流每 150ms 打开/关闭一次，共 20 次（模拟快速连点音量滑块）。Windows 每次都会丢一段音频，这找不回来；但虚拟声卡里不允许出现一个超过 t10/t11 阈值的硬台阶（丢失的两头必须是淡出/淡入） |

另有单元测试，覆盖路径规范化、路径通配符和环境变量展开、根进程选择（包括 PID 被复用的情况）、配置文件的读写和修复。

托盘程序的这些部分**没有自动化测试**，需要手动验证：菜单的外观和点击、文件选择框、通知气泡、悬停提示，以及 Explorer 重启后图标能否恢复。
t8 通过发送与菜单项相同的命令 ID（`WM_COMMAND`）来驱动托盘程序；运行测试时不能有另一个 `Ausieve.exe` 在运行。

参考实测值（Windows 10 19044 + VAC）：t1/t4/t5 的抑制量为 54–100dB，t6 的延迟约 37–42ms（缓冲 20ms）。

t10 会受到其他声音的干扰（被采集的是整个系统的声音），跑测试时请暂停其他音频。

环境变量：

| 变量 | 作用 |
|---|---|
| `AUSIEVE_CABLE` | 虚拟声卡名，默认 `Line 1 (Virtual Audio Cable)` |
| `AUSIEVE_TONE_DEVICE` | 测试音使用的播放设备，默认是系统默认设备。设为另一条空闲的虚拟线后，测试就完全静音 |
| `AUSIEVE_MAX_LATENCY_MS` | 延迟阈值，默认 50 |
| `AUSIEVE_DUMP=1` | t3 打印 10ms 粒度的包络 |
| `AUSIEVE_BUFFER_MS` | 测试中 capture 使用的缓冲 |
| `AUSIEVE_CAPTURE_EXE` | 用另一个 capture.exe 跑测试（新旧版本对比） |
| `AUSIEVE_STATS=1` | capture/tray 每秒向 stderr 打印诊断：采集包、抖动缓冲水位、欠载、丢弃、漂移控制的速度；另外每次晚到/丢失的包、每次补静音、每次欠载都单独打印一行，带 QPC 时间 |
| `AUSIEVE_NO_TIMELINE=1` | capture/tray 关闭时间轴对齐（见 [design.md](design.md)），只用于新旧对比 |
| `AUSIEVE_RAW_BUFFER_MS` | 测试自己的录音流的缓冲容量，默认与 capture 相同（5 秒） |
| `AUSIEVE_T6_DELAY_MS` | t6 中脉冲在它的流打开之后多久播放，默认 500 |

注意：

- 采到的是端点音效（声卡的“增强”功能等）处理之后的声音。测试音使用 `AUDCLNT_STREAMOPTIONS_RAW` 播放，尽量绕开这些音效。
- 测试期间，系统里其他正在播放的声音会混进录音，可能影响 t1–t5 的结果，跑测试时请暂停其他音频。
- Windows 的 Process Loopback 本身有一个现象：系统里**任何程序**开始或停止播放（哪怕是静音的流）时，它交付的数据里会有一个极小的台阶（约 -46dBFS）。这与本工具无关，用直接录原始 Process Loopback 的方式验证过。t10 用原始 Process Loopback 作参照，把这类台阶排除在外。
