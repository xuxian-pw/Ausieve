# 排障：虚拟线没有声音，或声音不对

适用于：RustDesk 的音频输入选 **System sound** 时正常，选虚拟线（例如 `Line 1`）时没有声音、断续、发闷，或像被降噪。

## 先确定断在哪一段

```
播放器 ─▶ ① 采集（排除一个程序） ─▶ ② Ausieve 独占写入虚拟线 ─▶ ③ Windows 共享录音（经过音效） ─▶ ④ RustDesk ─▶ 控制端
```

System sound 不经过 ①②③，所以它正常只说明播放器和 RustDesk 的传输没问题。

| 测量 | 结果 | 断在 |
|---|---|---|
| 进程回环（排除目标后） | 没有声音，但系统里有声音 | ①：播放器被一起排除了 |
| **独占**录虚拟线的录音端（绕开 Windows 音效） | 没有声音或和 ① 不一致 | ②：Ausieve 或虚拟声卡 |
| **共享**录虚拟线的录音端（RustDesk 走这条） | 独占正常，共享不正常 | ③：录音端的音效、音量或权限 |
| 共享录音 | 正常 | ④：RustDesk 或控制端 |

独占和共享各录一次，是区分 ② 和 ③ 最快的办法。

## 不用工具先查一遍

| 检查 | 不对时的表现 | 处理 |
|---|---|---|
| 控制端 RustDesk 是否对这台设备静音 | 什么都听不见。按设备保存，重连也不恢复 | 在远程窗口的工具栏里取消静音 |
| Ausieve 是否在运行，悬停提示有没有错误 | 完全没声音 | 启动它；它不会开机自启。有错误时按提示处理 |
| Ausieve 的输出和 RustDesk 的输入是不是同一条线的两端 | 完全没声音 | 输出选播放端，RustDesk 选录音端（`CABLE Input` 对应 `CABLE Output`） |
| 被控端 RustDesk 是否低于 1.5.3，且虚拟线两端同名（VAC 的 `Line 1` 就是） | 完全没声音 | 升级被控端的 RustDesk，见[下面的案例](#案例被控端的旧版-rustdesk-选中了同名的播放端2026-11) |
| Windows 的默认播放设备是不是虚拟线 | 其他程序放不出声音 | 改成真实的扬声器或耳机。这条线被 Ausieve 独占 |
| 播放端是否允许独占 | Ausieve 报输出错误 | 勾选“允许应用程序独占控制该设备” |
| 录音端是否静音、音量为 0、被禁用 | 完全没声音 | 在 `mmsys.cpl` → 录制里恢复 |
| 麦克风隐私是否允许桌面应用 | 录音端打不开或全是零 | 打开它。虚拟线的录音端也受这个开关限制 |
| 播放器是不是由被排除的程序启动的 | 只有它没声音 | 排除的是整棵进程树（例如从语音软件里点链接启动的浏览器）。关掉后从开始菜单重新打开 |
| 播放器是否用独占模式输出 | 只有它没声音 | 进程回环采不到独占流，改成共享输出 |
| 有没有别的程序独占录音端 | RustDesk 打不开这条线，独占方却有声音 | 在那个程序里关掉独占或换设备。错误码：已有的流 `0x88890004`，新开的流 `0x8889000A` |
| Ausieve 是否和播放器在同一个 Windows 登录会话 | 完全没声音 | 在播放声音的那个会话里启动 |
| 录音端有没有第三方音效或 AI 降噪 | 几乎没声音、只有人声或大声能过、发闷、延迟变大 | 见下一节 |

## 案例：第三方 AI 降噪处理了虚拟线（2026-11）

**症状**：System sound 正常。切到 Line 1 后先是几乎没有声音，偶尔有模糊的声音，听起来一直在被降噪。

**原因**：声音坏在 ③。电脑上装了 intelliGo 的音效驱动（`IGOAPO2.dll`），它登记在所有音频端点上，虚拟线也不例外。降噪会把不像人声的声音当成噪音去掉。

**实测**（与进程回环的波形逐样本比对）：

| 位置 | 相关系数 | 增益 | 延迟 |
|---|---|---|---|
| ① 排除目标后的采集 | 1.000 | 1.000 | 0 |
| ② 独占录 Line 1 | 1.0000 | 1.000 | 34 ms |
| ③ 共享录 Line 1 | 0.94–0.99 | 小声时低到 0.24 | 104 ms |
| 对照：没有这个驱动的电脑，共享录 Line 1 | 1.0000 | 1.000 | 30 ms |

**不够的办法**：

- 取消录音端的“启用音频增强”。注册表里 `disableSysFx` 已经是 1，共享录音仍然被处理。
- 用 RAW 选项录音。结果和默认方式相同。

**处理**：

1. 在它自己的软件（intelliGo Neptune）里关掉降噪。
2. 仍然不行时，在设备管理器 →“音频处理对象 (APO)”里**禁用**（不是删除）`intelliGo Audio Processing Object`，然后重启。想恢复时重新启用。这也会关掉真实麦克风上的这项降噪。

按上面处理后，使用者试听确认恢复正常。两步中具体是哪一步起的作用没有记录，修好后也没有再测波形。故障期间“被排除的程序出声时才听得到一点”的现象没有查明原因。

**怎么认出同类问题**：在 `HKLM\SOFTWARE\Microsoft\Windows\CurrentVersion\MMDevices\Audio\Capture\{端点}\FxProperties` 里查 CLSID 对应的 DLL。登记了不等于正在起作用，以独占和共享两次录音的差别为准。Realtek、Nahimic、各品牌主板或笔记本自带的“AI 降噪”都可能造成类似现象。

## 案例：被控端的旧版 RustDesk 选中了同名的播放端（2026-11）

**症状**：音频输入选 Line 1 后完全没有声音。被控端是 RustDesk 1.4.0，控制端是 1.5.3。

**原因**：声音断在 ④。1.5.3 之前的 RustDesk（`src/server/audio_service.rs` 的 `get_audio_input`）用 `HOST.devices()` 在播放和录音设备里一起按名字查找，取第一个。VAC 的两端都叫 `Line 1 (Virtual Audio Cable)`，播放端排在前面，于是它拿播放端去录音，打不开。1.5.3 改成了只在 `HOST.input_devices()` 里找。

核对过源码的版本：1.4.0–1.4.4、1.4.6、1.4.9、1.5.0、1.5.1 有这个问题，1.5.3 没有。两端名字不同的虚拟线（如 `CABLE Input` / `CABLE Output`）按这段逻辑不受影响。

**实测**：

| 检查 | 结果 |
|---|---|
| 独占、共享录 Line 1，与进程回环比对 | 相关系数都是 1.0000，增益 0.991、0.992，①②③ 都正常 |
| RustDesk 的录音会话 | 远程桌面连着、控制端没静音，但所有录音设备上都没有 |
| 全部设备的枚举顺序 | 同名两端中播放端在前（序号 2），录音端在后（序号 8），序号从 0 数 |
| 按名字找到的两端各自试着录音 | 播放端失败（`0x8889000A`，被 Ausieve 独占），录音端正常 |
| 控制端日志 | 被控端切到 Line 1 后，再没有 `recved audio format` |

没有看到 RustDesk 内部的报错原文（服务日志需要管理员权限），原因是由源码和上面的测量对出来的。

**处理**：把**被控端**的 RustDesk 升级到 1.5.3 或更新，只升级控制端没有用。升级后使用者试听确认恢复正常，控制端日志里一连上就收到了音频格式；没有再测波形。

不能升级时，按同一段源码可以这样绕开（没有实测过）：

1. 先把 RustDesk 的音频输入切到 System sound。否则改名后它找不到原来的名字，会改录默认麦克风。
2. 在 `mmsys.cpl` → 录制里把录音端改成不同的名字，例如 `Line 1 Rec`。播放端不要改，Ausieve 按名字找它。
3. 在 RustDesk 的音频输入里选新名字。

**怎么认出同类问题**：共享录音正常，但 RustDesk 在录音端没有会话。先看被控端的 RustDesk 版本，以及虚拟线两端是否同名。

## 测量时容易误判的地方

- **只看峰值会漏掉降噪。** 持续的大声能原样通过，坏的是小声、起音和高频。要比波形，并且看包含小声的一段时间。
- **测的时候一定要有连续的声音。** 视频暂停时所有位置都是零，什么也证明不了。
- **独占流的时间戳不能用来摆放样本**，要按到达顺序拼接，否则相关系数会掉到 0.2–0.4，看起来像是坏了。
- **独占录音会打断正在共享录音的程序。** RustDesk 通常会自己恢复；没有恢复时，把音频输入切到 System sound 再切回来。
- **改了音效设置之后要让录音流重新打开**，同样用切换音频输入的办法。
- **配置里找不到某一项，不等于找到了原因。** 先看实际的音频会话（谁开着哪个设备、是否活动），再下结论。
- **没有远程桌面连接或者控制端静音时，RustDesk 不会录音**，这时录音端没有 RustDesk 的会话是正常的。
- 进程回环的电平不受播放设备主音量影响，但受各程序自己的音量影响。
