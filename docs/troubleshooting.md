# 排障：远程听不到声音，或声音不对

适用于：通过 RustDesk 听 Ausieve 送进虚拟线（例如 `Line 1`）的声音时，没有声音、断续、发闷，或像被降噪。System sound 是否正常不是前提，它只是一个有用的对照。

这里写的是目标、已知的事实和现成的工具，**不是必须照做的步骤**。从哪里查起、用什么方法量，按现场判断。下面的原因和案例只是已经遇到过的，新问题很可能不在里面；测量和这份文档矛盾时，以测量为准，并把文档改掉。

## 查到什么程度算完

- 能用证据说出声音断在哪一段，并分清哪些是测到的、哪些是推断的。
- 改完以后，使用者通过 RustDesk 实际听过。最好同一个场景对比 System sound 和虚拟线。
- 新的原因、被推翻的结论，补回这份文档。

## 声音经过哪里

```
被控端                                                                                                   控制端
播放器 ─▶ ① 采集（排除一个程序） ─▶ ② Ausieve 独占写入虚拟线 ─▶ ③ Windows 共享录音（经过音效） ─▶ ④ RustDesk ─▶ ⑤ RustDesk 播放
```

| 段 | 什么能证明它正常 | 光凭什么还不能下结论 |
|---|---|---|
| ① | 一个确知不在排除范围内的声源，出现在“排除目标后”的进程回环里 | 排除后为零：也可能当时只有被排除的程序在出声 |
| ② | **独占**录录音端（绕开 Windows 音效），波形和 ① 一致 | Ausieve 在运行、有音频会话 |
| ③ | **共享**录录音端（RustDesk 走这条），波形和 ① 一致。它正常时 ①② 也就正常，不必再做独占测试 | 峰值相同、没登记音效 DLL |
| ④ | 远程桌面连着时，被控端 RustDesk 在录音端有活动会话 | 设置里选了这条线：选了不等于打开了 |
| ⑤ | 被控端确实在出声时，控制端 RustDesk 的播放会话有电平 | 播放会话是活动的、没有静音 |

System sound 不经过 ①②③，也不走 ④ 里“按名字找录音设备”的那段代码。它正常，只说明编码、传输和 ⑤ 没问题，不能排除 ④。

## 可以用的工具

[`scripts/diagnose.ps1`](../scripts/diagnose.ps1) 一次量出上面各段。它是仓库里的开发工具，不随安装包提供；单个文件，不依赖仓库里的其他东西，可以拷到没有仓库的电脑上用。

```powershell
powershell -NoProfile -ExecutionPolicy RemoteSigned -File scripts\diagnose.ps1
```

| 在哪台运行 | 参数 | 得到什么 | 影响 |
|---|---|---|---|
| 被控端 | 无 | 配置、设备、音效、RustDesk 版本和会话，①③ 的波形对比，约 25 秒 | 不断音 |
| 被控端 | `-Tone` | 同上，自带一个已知声源 | 那台会听到很轻的扫频声 |
| 被控端 | `-Exclusive` | 再加 ② 的独占录音，用来分开 ② 和 ③ | 远程声音断约 14 秒，旧版 RustDesk 可能不会自己恢复 |
| 控制端 | `-Client` | 静音标志、音频日志、⑤ 的电平，约 5 秒 | 不断音 |

- 要在播放声音的那个 Windows 登录会话里运行，不需要管理员。`Get-Help` 能看到其余参数。
- `FINDINGS` 只是按数字给出的提示，结论要回到它上面的原始数据核对。脚本不够用或者判断错了，就自己另写测量，或者改它。
- 报告在 `%TEMP%`，里面有程序名和设备名，公开之前先看一遍。

想自己查时，信息在这些地方：

| 要看什么 | 在哪里 |
|---|---|
| Ausieve 的输出和排除对象 | `%APPDATA%\Ausieve\config.toml`。它没有日志，错误在托盘的悬停提示里 |
| 设备的准确名字 | 安装目录里的 `capture.exe --list-devices`；启用和禁用看 `mmsys.cpl` |
| RustDesk 选的音频输入 | `%APPDATA%\RustDesk\config\RustDesk2.toml` 的 `audio-input`（同一目录里有密码和密钥，只取需要的行） |
| 控制端是否静音 | `%APPDATA%\RustDesk\config\peers\*.toml` 的 `disable_audio` |
| 控制端有没有收到音频流 | `%APPDATA%\RustDesk\log\rustdesk_rCURRENT.log` 里的 `recved audio format` |
| 登记的音效 | `HKLM\SOFTWARE\Microsoft\Windows\CurrentVersion\MMDevices\Audio\Capture\{端点}\FxProperties` |
| 麦克风隐私（也管虚拟线的录音端） | `HKLM`、`HKCU` 下 `SOFTWARE\Microsoft\Windows\CurrentVersion\CapabilityAccessManager\ConsentStore\microphone` |

## 容易得出错误结论的地方

- **没有已知声源时，零什么也证明不了。** 视频暂停、只有被排除的程序在出声、控制端测的那几秒恰好没声音，看起来都像故障。
- **只看峰值会漏掉降噪。** 持续的大声能原样通过，坏的是小声、起音和高频。要比波形，并且包含小声的一段时间。
- **太小的声音不能拿来比波形。** 经过虚拟线后相当于 16 位：RMS 0.00003–0.00008 的底噪实测增益只剩 0.4–0.7、相关系数 0.78–0.97，而线本身是好的。脚本只比较 RMS 不低于 0.001 的片段，所以更小声处的降噪它看不出来。
- **配置或注册表里有，不等于正在起作用；没有，也不等于找到了原因。** 看实际的会话和波形。
- **RustDesk 只在需要时录音。** 没有远程桌面连接或控制端静音时，录音端没有它的会话是正常的。
- **独占录音会打断 RustDesk。** 1.4.0 的录音流出错后不会重建，需要把音频输入切到 System sound 再切回来；改过音效设置后也要这样重开一次录音流。
- **独占流的时间戳不能用来摆放样本**，要按到达顺序拼接，否则相关系数会掉到 0.2–0.4，看起来像是坏了。
- **注册表里的设备状态和名字不能直接用。** `DeviceState = 0x10000001` 是禁用，不是可用；拼出来的名字也可能缺 `2- ` 这样的前缀。以 Core Audio 枚举的为准。
- **RustDesk 找不到所选名字的设备时会改录默认麦克风**，不报错。听到的是环境声时先想到它。
- **两台电脑的时钟可能差几十秒**，对照两边日志之前先量一下。
- 进程回环的电平不受播放设备主音量影响，但受各程序自己的音量影响。安全软件在程序打开录音设备时播放的提示音也会被录进去。

## 遇到过或已知会造成问题的原因

用来启发，不是完整清单，也不用按顺序查。

| 段 | 原因 | 表现 | 处理 |
|---|---|---|---|
| ① | 播放器是由被排除的程序启动的 | 只有它没声音 | 排除的是整棵进程树（例如从语音软件里点链接启动的浏览器）。关掉后从开始菜单重新打开 |
| ① | 播放器用独占模式输出 | 只有它没声音 | 进程回环采不到独占流，改成共享输出 |
| ① | Ausieve 和播放器不在同一个登录会话 | 完全没声音 | 在播放声音的会话里启动 Ausieve |
| ② | Ausieve 没运行或报错 | 完全没声音 | 启动它（不会开机自启），按错误提示处理 |
| ② | 播放端不允许独占，或被别的程序占用 | Ausieve 报输出错误 | 勾选“允许应用程序独占控制该设备”，或关掉占用它的程序 |
| ② | 虚拟线被设成默认播放设备 | 其他程序放不出声音 | 改成真实的扬声器或耳机 |
| ③ | 录音端静音、音量为 0、被禁用 | 完全没声音 | 在 `mmsys.cpl` → 录制里恢复 |
| ③ | 麦克风隐私不允许桌面应用 | 打不开或全是零 | 允许桌面应用访问麦克风 |
| ③ | 第三方音效或 AI 降噪 | 几乎没声音、只有人声能过、发闷、延迟变大 | 见[降噪的案例](#案例第三方-ai-降噪处理了虚拟线2026-11) |
| ③ | 别的程序独占了录音端 | RustDesk 打不开这条线 | 错误码：已有的流 `0x88890004`，新开的流 `0x8889000A` |
| ④ | 被控端 RustDesk 低于 1.5.3，且线的两端同名（VAC 的 `Line 1` 就是） | 完全没声音 | 升级被控端，见[同名播放端的案例](#案例被控端的旧版-rustdesk-选中了同名的播放端2026-11) |
| ④ | 选错了端或设备，或者选的设备改了名 | 没声音，或听到麦克风 | Ausieve 输出选播放端，RustDesk 选同一条线的录音端（`CABLE Input` 对应 `CABLE Output`） |
| ⑤ | 控制端对这台设备静音 | 什么都听不见。按设备保存，重连也不恢复 | 在远程窗口的工具栏里取消静音 |

## 案例：第三方 AI 降噪处理了虚拟线（2026-11）

**症状**：System sound 正常。切到 Line 1 后先是几乎没有声音，偶尔有模糊的声音，听起来一直在被降噪。

**原因**：声音坏在 ③。电脑上装了 intelliGo 的音效驱动（`IGOAPO2.dll`），它登记在所有音频端点上，虚拟线也不例外。降噪会把不像人声的声音当成噪音去掉。

**实测**（与进程回环的波形逐样本比对）：

| 位置 | 相关系数 | 增益 | 延迟 |
|---|---|---|---|
| ① 排除目标后的采集 | 1.000 | 1.000 | 0 |
| ② 独占录 Line 1 | 1.0000 | 1.000 | 34 ms |
| ③ 共享录 Line 1 | 0.94–0.99 | 小声时低到 0.24 | 104 ms |
| 对照：没有这个驱动的电脑，共享录 Line 1 | 1.0000 | 1.000 | 30 ms |

**不够的办法**：

- 取消录音端的“启用音频增强”。注册表里 `disableSysFx` 已经是 1，共享录音仍然被处理。
- 用 RAW 选项录音。结果和默认方式相同。

**处理**：

1. 在它自己的软件（intelliGo Neptune）里关掉降噪。
2. 仍然不行时，在设备管理器 →“音频处理对象 (APO)”里**禁用**（不是删除）`intelliGo Audio Processing Object`，然后重启。想恢复时重新启用。这也会关掉真实麦克风上的这项降噪。

按上面处理后，使用者试听确认恢复正常。两步中具体是哪一步起的作用没有记录，修好后也没有再测波形。故障期间“被排除的程序出声时才听得到一点”的现象没有查明原因。

**怎么认出同类问题**：在 `HKLM\SOFTWARE\Microsoft\Windows\CurrentVersion\MMDevices\Audio\Capture\{端点}\FxProperties` 里查 CLSID 对应的 DLL。登记了不等于正在起作用，以独占和共享两次录音的差别为准。Realtek、Nahimic、各品牌主板或笔记本自带的“AI 降噪”都可能造成类似现象。

## 案例：被控端的旧版 RustDesk 选中了同名的播放端（2026-11）

**症状**：音频输入选 Line 1 后完全没有声音。被控端是 RustDesk 1.4.0，控制端是 1.5.3。

**原因**：声音断在 ④。1.5.3 之前的 RustDesk（`src/server/audio_service.rs` 的 `get_audio_input`）用 `HOST.devices()` 在播放和录音设备里一起按名字查找，取第一个。VAC 的两端都叫 `Line 1 (Virtual Audio Cable)`，播放端排在前面，于是它拿播放端去录音，打不开。1.5.3 改成了只在 `HOST.input_devices()` 里找。

核对过源码的版本：1.4.0–1.4.4、1.4.6、1.4.9、1.5.0、1.5.1 有这个问题，1.5.3 没有。两端名字不同的虚拟线（如 `CABLE Input` / `CABLE Output`）按这段逻辑不受影响。

**实测**：

| 检查 | 结果 |
|---|---|
| 独占、共享录 Line 1，与进程回环比对 | 相关系数都是 1.0000，增益 0.991、0.992，①②③ 都正常 |
| RustDesk 的录音会话 | 远程桌面连着、控制端没静音，但所有录音设备上都没有 |
| 全部设备的枚举顺序 | 同名两端中播放端在前（序号 2），录音端在后（序号 8），序号从 0 数 |
| 按名字找到的两端各自试着录音 | 播放端失败（`0x8889000A`，被 Ausieve 独占），录音端正常 |
| 控制端日志 | 被控端切到 Line 1 后，再没有 `recved audio format` |

没有看到 RustDesk 内部的报错原文（服务日志需要管理员权限），原因是由源码和上面的测量对出来的。

**处理**：把**被控端**的 RustDesk 升级到 1.5.3 或更新，只升级控制端没有用。升级后使用者试听确认恢复正常，控制端日志里一连上就收到了音频格式；没有再测波形。

不能升级时，按同一段源码可以这样绕开（没有实测过）：

1. 先把 RustDesk 的音频输入切到 System sound。否则改名后它找不到原来的名字，会改录默认麦克风。
2. 在 `mmsys.cpl` → 录制里把录音端改成不同的名字，例如 `Line 1 Rec`。播放端不要改，Ausieve 按名字找它。
3. 在 RustDesk 的音频输入里选新名字。

**怎么认出同类问题**：共享录音正常，但 RustDesk 在录音端没有会话。先看被控端的 RustDesk 版本，以及虚拟线两端是否同名。
